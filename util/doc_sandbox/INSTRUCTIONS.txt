Documentation Notes 
-------------------

Sandbox utility doc generation using mkdocs

(Note: This code documentation is separate from the webpage plot
documentation in Local/www-doc.)

Rationale: mkdocs uses markdown, is Python-focused, supports extra
(non-code) documentation, and can export docs to github.

In this dir, we're using mkdocs to make narrative documentation for
Sandbox basic operating principles, and for command-line utility
scripts.  (See mkdocs.yml for the file contents.)

My patience was low so I have missed some affordances mkdocs has
for my use case. Here's the approach we took:

* mkdocs wants to document a python package; the Sandbox is mostly
utility scripts and *there is no base package*. So this directory
(below util/) is the pseudo-package for "exosims_sandbox", for 
documentation purposes. (TODO: bring the Sandbox itself more in 
line with a conventional package.)

* To document command-line utilities, we use `gen-pages.py` to
extract the documentation block telling usage.

* In a small number of cases (e.g., drm_tabulate.py), the code
itself seemed worth documenting. For those scripts: we add ../
to the Python path (see mkdocs.yml) so we can find the 
source code in ../util, allowing conventional
code documentation; (2) we added a manual entry to doc/implementation
pointing to that file.

We are using "uv" to manage the dependencies. We have pinned the
mkdocs (and related) versions a stable version - there has been
churn among mkdocs maintainers. See pyproject.toml for more and
for the pinned versions.

Basic operating principles:
  - static .md files pointing to some .png diagrams
    e.g., the budding reference homepage:
      docs/reference.md 

Command-lines:
  - gen_pages.py, a mkdocs plugin, generates .md files containing
    the usage information for all util/ commands, at runtime, 
    whenever mkdocs build is run

To add a new source file (new.py) to the detail list:
  - Place a markdown in docs/implementation/new.md, with a :::
    pointer showing how to import it.
  - Ensure it can be imported when "mkdocs build" is run.
  - Nothing else is needed: gen_pages.py looks for
    docs/implementation/<stem>.md and links to it from the script index
    when it is there.

Plot documentation:

The per-plot reference pages under Local/www-doc are rendered twice, from
one source. Local/www-doc/Makefile renders them with markdown+m4 for the
sandbox web UI, where they are deep-linked next to the plots themselves
(see WWW_DOC in util/html-summary.py). gen_pages.py *also* reads them and
writes them into this site under plots/, which is what puts them into the
exported and github-pages documentation. Nothing is written back to
Local/www-doc.

Consequence: adding a plot page means naming it in two lists -- TOPICS in
Local/www-doc/Makefile, and the "Plot Reference" nav in mkdocs.yml here.
"make doc-lint" from the Sandbox root checks that they agree, which seemed
better than taking on a literate-nav dependency to avoid the duplication.

Docstring conventions:

The documentation block is what gets rendered, so it has to be Markdown.
util/drm_tabulate.py is the model. In brief:

  - First line is "name.py: one-line summary". gen_pages.py builds the
    Script Index description by finding the script's own name in the
    block, so a block that never names the script gets a bare index entry.
  - Usage lines and option lists go inside ``` fences. Indentation alone
    does not work: markdown needs 4 spaces, and these blocks are
    conventionally written at 1-3, so they reflow into one paragraph.
  - A closing fence carries no info string. ```shell opens a block;
    it never closes one.
  - Prose is prose; use + or * bullets and backticks for flags.

"make doc-lint" (util/dev/doc-lint.py) checks all of the above, plus the
plot-topic lists. It is reporting-only.

See the Makefile here for some usage lines. Also:

# build the docs
uv run mkdocs build

# serve on localhost:8000
uv run mkdocs serve

More on methods (dated):
https://realpython.com/python-project-documentation-with-mkdocs/#step-1-set-up-your-environment-for-building-documentation
